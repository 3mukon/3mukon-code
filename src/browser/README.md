## Responsibilities

- `EmbeddedBrowser` owns tabs independently of their presentation. `none` uses an in-memory partition for one session across its turns. Session close releases its tabs and clears that partition. `app` uses one persistent app-owned partition. Each tab has its own session owner and operation grant. Clearing the app profile's sign-ins closes its tabs before clearing that partition.
- The loopback MCP tools reserve a tab with `browser_open`, then load an HTTP(S) address with `browser_navigate`. The default is `none`. A `global` request uses the connected Chrome profile. A saved connection comes back on its own once the app listens for it, as it starts or after the connection drops, since the extension tries again every 30 seconds; a `global` request in the 35 seconds after that waits for it (`liveTab`). With no connection live after that, before Connect or while connecting, a `global` request is refused as needing setup, which the session's setup notice shows, since background work never starts Chrome. The broker authorizes a shared-tab operation separately from the connection. A Chrome task tab opens blank, so nothing but a navigation may use it before its first page.
- `browser_snapshot` returns top-level page text and supported visible controls with an observation ID. `browser_act` clicks a control, sets a supported editable field or scrolls. A fresh semantic snapshot is required for each action. The isolated script checks the document, viewport, element and its current bounds before acting. A click is reported as dispatched. A field change or scroll can verify its immediate result. `browser_screenshot` returns a bounded viewport image with capture geometry. `browser_close` releases an owned tab.
- For `browser_act`, the broker records the validated action kind at request time, including for calls that are later refused or stopped. A label is taken from the caller's current observation of the owned tab. Entered text stays in the execution arguments.
- The renderer part (`renderer/browser-use.tsx`, ADR-0027): **Browser use** can clear shared app-browser sign-ins. For a Chrome adapter it lists the profiles by their names to connect one, and reports connecting, connected, saved-connection waiting, too old, no profiles yet and unavailable states, in the tones `renderer/chrome-state.ts` gives them. Disconnect is available while the saved Chrome profile is waiting, and also when Chrome is no longer installed. `BrowserSetupNotice` (`renderer/browser-notice.tsx`) offers Connect for a browser operation that needs Chrome connected. From the user's click it reads Chrome's setup and connects the only profile or the one chosen from a menu. Afterwards, Chrome's reported state replaces the button, including Connected when Chrome was connected elsewhere. Setup actions start only from the user's click.
- The setup snapshot reads Chrome’s version from its installed bundle and reports the adapter’s verified minimum.
- Profile discovery uses the directory keys and display names in Chrome's profile index, which the app always reads first. macOS 27 protects Chrome's data folder: a read it refuses fails without a prompt, and the user's selection of the folder in the system picker lets the app read it, also after the app starts again, until the Mac restarts. So only a refused read makes Connect open the picker at that folder, and after the user confirms the folder, Connect uses the profiles the app reads then. A folder other than Chrome's is refused, and Settings and the notice say so and how to select the right one. With no profile, Chrome reads No profiles yet, with how to create one; an index the app cannot read makes Chrome unavailable. Cancelling the picker starts no setup, and a saved connection restores without reading the profile index.
- The Chrome extension opens inactive task tabs and connects through a bundled native host to a private app socket (ADR-0030). Its manifest carries the extension's public key, which fixes its ID; secret scanning exempts that one line (`.gitleaksignore`). It keeps the paired profile and restores a new connection after either process exits. The extension intercepts attachments and applies a session-scoped Chrome response policy to its own tabs.
- `sh scripts/package.sh` bundles the signed Chrome host and unpacked extension. Connect from Settings or a session notice checks the chosen profile through a temporary loopback page. For its first installation, Settings and the notice offer **Copy Folder Path** for the extension folder. In the same Chrome window, open **Manage Extensions**, enable Developer mode and select that folder using **Load unpacked**. Keep the setup tab open while the app pairs. The installed folder lives in app data so Chrome can use it again after an app or browser restart. `scripts/build-chrome-profile-candidate.mjs` also stages the connector for isolation tests.
- `main/chrome-connector.ts` installs the host, the extension and the host's registration at Connect, and renews what is installed as the app starts, before Chrome can connect (ADR-0032). `scripts/stamp-chrome-extension.mjs` names the staged extension's build by its files in `build.js`; the source folder's build is `development`. The worker reloads the extension when its folder holds another build than the worker runs, and never while it has a connection. Pairing and restoring name the build, and the app takes only its own. The setup page counts an extension of another build as missing once it has had time to reload. An extension loaded from another folder cannot follow: its connection waits until Disconnect and Connect lead to loading the app's folder.
- An external panel shows stills of its bound tab and their age. Fresh frames use the broker's active browser operation signal. If that operation ends during capture, the view discards the result and can show the last matching frame at its original capture time. Open in Chrome uses the trusted window command to select the bound tab. Releasing a Chrome task tab closes it unless the user took it over.
- `BrowserPanel` (`renderer/browser-panel.tsx`, ADR-0027) is a tab of the app's browser in a panel, whose header the app module gives the page's title and host and how it is shared: above the page, Back, Forward and Reload, Reload turning into Stop Loading while the page loads, and the page's address in a dashed field, with a lock for a secure page; under them the page in its frame, with the window's paper over it while it loads, once it cannot load, saying why, with Try Again, and while the tab is blank, and the paper alone once the tab has closed. While the agent acts, a thin line in the accent runs along the frame's top edge, and a chip under the frame names the session, with Stop; while the user has the tab, the chip says so, with Hand Back; while the agent waits for the user's answer to work in the tab, it says so, with Show, and the page stays the user's. The chip has a strip of its own under the frame, kept while the session holds the tab (`TabUse`), since the page draws over anything in its frame, and since a page that changes size makes the agent's observations stale. It takes the tab's state and sends the user's controls through whoever composes it, saying when one did not go. A Chrome tab stays in Chrome. its panel's line says it is a preview that takes no input, with the age of the frame the page view reports, beside Open in Chrome, which brings that same tab to the front; it has no Back, Forward, Reload or address field, and its chip names the browser the agent acts in. The page comes as a function of the panel's report of its frame's capture time.
- `BrowserPageView` (`renderer/browser-page-view.tsx`) lays the tab's live page in the frame through the view port: it binds the tab to its presentation, asking again while main has not heard that the panel opened, places the page wherever its box goes, with a newer revision each time, covered while something the ui module's covers register lies over it, then showing the still frame or the paper with the page's title and address that main answers, dimmed with the paper's colour while the panel has no focus, focusing the panel at the click main reports, and lets the page go when its box goes; where main lets a binding go, it binds again a few times. For a Chrome tab (`previewRevision`), it shows still frames, faded as a preview, asked for anew each second, and reports each frame's capture time (`onFrame`). When main reports a file dragged from the Finder entering the page (`onFileDrag`), the page lies under a cover for a moment, through the drop, so that the app's own drop takes the file and the page never receives it. `useBrowserTabs` (`renderer/use-browser-tabs.ts`) resolves and follows the tabs the window's browser panels show, for the app module.
- `ElectronEmbeddedEngine` creates detached, sandboxed `WebContentsView` instances with their own sessions and no app preload. An empty `about:blank` document initializes Chromium before the main process installs its containment commands. The engine removes that bootstrap entry from history when the first website commits. It blocks popup, chooser, download and permission paths and disables native page dialogs. Its document script returns Cancel-compatible results for alert, confirm and prompt. The engine enables CDP runtime events to report bounded dismissal types through the active call and its activity record.
- `BrowserViewHost` attaches the tab's existing view only for an acknowledged browser item in an open presentation. It clips the reported bounds to the window in device-independent pixels and drops the binding when the presentation or renderer leaves. While the tab loads, or after it failed to load, the view stays off the window so that the panel's paper shows; once the page has loaded, the view returns where the panel last asked for it live, with its dimming, since the panel asks again only when its box or its covers change. A cover or a parked box meanwhile leaves it off until the panel asks again. The tab's page and session belong to the browser, so the same tab can be shown again without navigation.
- File drags are blocked inside the page and its frames. A trusted drag entering the native page or dimmer parks that view and reports the binding to the app renderer. The panel area handles file drops through the app's existing drop path. The embedded renderer has no app preload or access to the app's file grants.

## Not responsible for

- Session authority, grants and record retention belong to the toolset. The app and panels modules compose the renderer, choose the page's available bounds and report overlay coverage. The Chrome adapter is separate from embedded browsing (ADR-0031).

## Interface

- `shared/browser.ts` defines the `BrowserTabs` port for user controls and state subscriptions, including title, address, sharing, profile, loading, navigation history and takeover. The user's Close, from a tab's row above the composer, ends the tab and the agent's use of it whoever has the tab, as closing the session would; a Chrome task tab the user took over stays open in Chrome as the user's own. `shared/browser-fake.ts` drives the same port in panel tests. App composition supplies the backend's resource and grant ports through `src/app/main/browser-automation.ts`.
- `shared/view.ts` defines the view port. Resolve the session's tab via `tabRef`, wait for a loaded tab and an acknowledged open presentation, then `bind` it. Call `place` with an increasing revision whenever the bounds or visibility change. Use null bounds to park it. Use `covered` for overlays intersecting the page body. A cover parks the native view immediately and returns a current frame, a generation-matching kept frame with its capture time, or paper within 100 ms of main handling the request. A native view sits above renderer content at the same bounds, so a renderer control needs its own space or the cover path. `onFocus` reports a user click. Release the binding when the page body goes away. The port is served only to the trusted app renderer and keeps overlay frames away from model tool results.
- `main/page.ts` defines the page-engine interface and fixed observation and action shapes. An external tab carries its browser kind and connection key. The session registry scopes external tab leases by browser and reports the adapter's browser in the tab state and resource summary. The engine interface lets broker tests exercise session and tab policy with a synthetic engine.

## Dependencies

- Session automation facts, Electron, Node.js and zod. App composition connects the module to the broker and presentation host.

## Invariants

- Tab IDs are scoped by owner and generation. A shared sign-in does not transfer another session's tab. Snapshots expose at most 64 supported controls and about 2,000 characters of page text. Normalized summaries omit URL query strings and fragments. There are no APIs for cookies, local storage, form values or arbitrary scripts. Screenshots are page pixels and may include visible sensitive content.
- The background path does not attach a view to a window or send OS input. Real-page containment and unattended capture are covered by isolated-window verification before delivery.
- Programmatic placement preserves focus. A sandboxed paper-color layer dims the view and consumes a click, reporting it to the renderer. Once the live page accepts a click, real page input can give the user control and end the agent's operation. A viewport resize invalidates coordinate and element observations. Native z-order and focus behavior require isolated app verification.
