## Architecture decisions

| ID | Status | Title | Summary |
|---|---|---|---|
| [ADR-0002](adr/ADR-0002-desktop-app-stack.md) | accepted | Build the desktop app with Electron and TypeScript | Electron with TypeScript, because it keeps every provider integration, the Claude Agent SDK included, in one process and one language and reuses the most code; a SwiftUI app with a TypeScript provider process, an all-Swift app and Tauri were rejected |
| [ADR-0003](adr/ADR-0003-provider-protocols.md) | accepted | Drive Codex through app-server and Grok Build through ACP agent mode | Codex runs as `codex app-server` and Grok Build as `grok agent stdio`, because only these interfaces let the app answer approvals and questions while a turn runs; the Codex SDK, `codex exec`, `codex mcp-server`, Grok Build's headless mode and third-party ACP adapters were rejected |
| [ADR-0005](adr/ADR-0005-provider-neutral-session-model.md) | accepted | Model every session as one provider-neutral event stream | Each provider adapter maps its protocol onto one internal interface, a session that reports serializable events and takes answers to approvals and questions, using ACP's tool vocabulary, unified diffs and per-request approval options; adopting ACP itself as the internal model and building a UI per provider were rejected |
| [ADR-0006](adr/ADR-0006-two-permission-modes.md) | accepted | Offer two permission modes, automatic approval by default and yolo | Every provider runs in one of two modes, auto, in which the provider's own automatic review approves or denies each action and asks the user only when it cannot decide, and which new sessions start in, or yolo, in which nothing is asked; asking before every action and the providers' other modes are not offered |
| [ADR-0007](adr/ADR-0007-icons-from-lucide.md) | accepted | Take the app's icons from Lucide, through the ui module | The UI takes its icons from Lucide (`lucide-react`, ISC licence), which the ui module re-exports as decorative components so that no other module imports the set directly; hand-drawn icons and SF Symbols were rejected |
| [ADR-0010](adr/ADR-0010-math-and-code-in-messages.md) | accepted | Set the math in messages with KaTeX and highlight their code with highlight.js, as Markdown plugins | Messages set math with KaTeX through remark-math and rehype-katex, its fonts bundled, and highlight fenced code with highlight.js through rehype-highlight in the tokens' Flexoki syntax colours, because both run synchronously inside react-markdown and work offline; MathJax, Shiki and Prism were rejected |
| [ADR-0011](adr/ADR-0011-code-editor.md) | accepted | Edit files with CodeMirror 6, assembled from its packages | The file editor is CodeMirror 6, assembled from its packages, with each file's language loaded on demand through CodeMirror's language data and its look and syntax colours taken from the tokens, because it is modular, stays fast on large files, edits real text for macOS's input methods and VoiceOver, needs no workers or network and follows both appearances through CSS; Monaco Editor, Ace and a highlighted textarea were rejected |
| [ADR-0013](adr/ADR-0013-menus-and-questions-in-the-page.md) | accepted | Draw the main process's menus and questions in the window's page, in the app's own look | The main process keeps deciding what it asks the user, but its context menus and confirmation questions go to the window's page as plain data, which draws them with the ui module's menu and question in the e-ink look and sends back the answer; macOS's menus and sheets, which cannot take that look, flows driven from the page and a window of its own per question were rejected, and the file panels and the question while a page unloads stay macOS's own |
| [ADR-0014](adr/ADR-0014-session-texts-for-search.md) | accepted | Keep the text of each session's messages in the app's data, for searching | The app keeps the text of each session's messages, the user's and the agent's, in a file of its own in the app's data, written as turns end, sessions close and histories are read and caught up in the background for older sessions, so that the lists search by conversation at once; reading every history at each search, searching only the histories already read, a SQLite full-text index and reading the providers' own files were rejected |
| [ADR-0015](adr/ADR-0015-terminal-library.md) | accepted | Run terminals in pseudo-terminals from node-pty in the main process, and draw them with xterm.js | A terminal panel's shell runs in a pseudo-terminal from node-pty 1.2.0-beta.18 in the main process, whose prebuilt macOS binary loads in Electron without a rebuild, and the window draws it with xterm.js 6 and its fit and web-links addons; node-pty 1.1.0, whose prebuilt spawn helper is packed without its execute bit, its repackagings, building it from source, macOS's script command and other emulators were rejected |
| [ADR-0016](adr/ADR-0016-terminal-as-a-pipe.md) | accepted | Treat a terminal as a pipe between the user and its programs, which the app never reads, keeps or logs | What runs in a terminal panel and what it prints pass between the pseudo-terminal and the window's emulator without the app reading, keeping or logging them, and are gone when the panel closes, so that a terminal, the providers' sign-in commands included, stays within invariant 9 as it is worded; changing the invariant, leaving sign-in to macOS's Terminal, reading the sign-in commands' output and the providers' programmatic sign-ins were rejected |
| [ADR-0017](adr/ADR-0017-sign-in-and-usage-sources.md) | accepted | Read each provider's sign-in and usage limits through its adapter, from the calls each provider offers, and ask rarely | Each adapter reads its provider's sign-in and a subscription's usage limits, through a running session's process where one is open and otherwise a short-lived one, from Claude Code's sign-in status and experimental usage call, Codex's app-server account calls and Grok Build's undocumented `x.ai/auth/info` and `x.ai/billing`, with the limits that turns report on their own; the app asks once after the window opens, then only when the Accounts panel shows data over five minutes old, every five minutes while it shows, after a reset or a sign-in, and keeps the limits it read in its data; calling the providers' web endpoints, parsing their commands' text and polling were rejected |
| [ADR-0018](adr/ADR-0018-rendered-file-views.md) | accepted | Render files in the window, Markdown with the activity's renderer moved to the ui module and the data formats as one folding tree | A file's rendered view is drawn in the window by the files module: Markdown with the activity's renderer, which moves to the ui module so that the sessions and files modules share it; JSON, YAML, TOML and XML as one folding tree of the app's own over JSON.parse, yaml 2, smol-toml and the window's DOMParser; CSV and TSV as a table from a reader of the app's own; and SVG as an image, which runs none of its scripts; copying the renderer, viewer libraries per format and drawing files in frames were rejected |
| [ADR-0019](adr/ADR-0019-login-shell-path.md) | accepted | Give the packaged app the login shell's PATH, and nothing else of the shell's environment | As it starts, the packaged app reads the PATH the user's login shell sets, from an interactive login shell's own printenv between two marks within five seconds, and runs the providers and terminals with it, since an app opened from the Finder has macOS's minimal PATH, which the agents' commands outgrow; taking the shell's whole environment, which may hold the credentials a profile exports, a fixed list of folders and asking the user to set launchd's PATH were rejected |
| [ADR-0020](adr/ADR-0020-provider-default-task-tools.md) | accepted | Follow each provider's own default for its task tools | The app turns on no provider's task tools and shows a session's task list wherever the provider's agent keeps one, since Claude Code now offers its task tools by default only to its older models and Codex keeps its plan tool off, and turning them on for every session would spend tool calls in every multi-step turn and move the agents off their makers' defaults; turning them on for every session and a setting of the app's own were rejected |
| [ADR-0021](adr/ADR-0021-tooltips-in-the-page.md) | accepted | Draw tooltips in the window's page, in the app's own look, from the titles the controls already carry | One host in the page draws the window's tooltips, while a setting that starts off allows them, as a sheet of the paper under a dashed line, from the `title` each control already carries, which waits aside while the pointer is over it so that macOS's own tooltip stays away, because Electron shows macOS's tooltips only now and then and they cannot take the e-ink look; macOS's own tooltips, a tooltip at each control and a tooltip library were rejected |
| [ADR-0023](adr/ADR-0023-session-owned-automation-broker.md) | accepted | Keep automation authority and lifetime in a session-owned broker behind the shared toolset | Populate the existing HTTP toolset through a session-owned broker that binds callers before provider startup and owns grants, cancellation and resource lifetimes outside individual MCP requests |
| [ADR-0024](adr/ADR-0024-browser-resources-and-adapters.md) | accepted | Own browser resources separately from their views and connect daily browsers through explicit adapters | Keep browser contexts independent of panels, using Electron for isolated and app sharing, an extension-backed Chrome connection and two Safari extension roles with explicit binding and capability gates |
| [ADR-0025](adr/ADR-0025-app-owned-native-helper.md) | accepted | Run native automation in a signed helper with app-owned state and explicit control leases | Use focused PeekabooAutomationKit source in a lazily started signed helper with an explicit coordination root, target-bound observations and cancellable leases, without another model runtime |
| [ADR-0026](adr/ADR-0026-acknowledged-panel-commands.md) | accepted | Apply panel tools through acknowledged renderer commands and durable dismissal state | Keep the renderer authoritative for panel layout while the host sends scoped revision-checked commands, waits for acknowledgement and remembers the user's closes across reconnects and reloads, telling the agent of each and never undoing one with an update |
| [ADR-0027](adr/ADR-0027-browser-and-computer-use-and-closed-panels.md) | accepted | Show agents' browser and computer use in their sessions and in panels, ask once for each operation beyond a session's reach, and tell agents of the presentations the user closes | What agents do in browsers and other applications shows in their session's activity and in a line above its composer, a page or another application's window opens as a panel beside the session only when presented and without the focus, the agent is told when the user closes one and is instructed not to reopen it without good reason, foreground control shows a small floating control with Stop, and each operation beyond what a session reaches unasked asks once in place with the approvals' own answers, because the user often works in the same window or on the same Mac and must see, grant and stop what acts as them; a window of its own for automation, a menu bar indicator, approvals for each action or for a whole task, marks on presented panels and a click to confirm every reopening were rejected |
| [ADR-0028](adr/ADR-0028-codex-gateway-settings-and-defaults.md) | accepted | Pass a Codex gateway file's settings to Codex, token included, and show only its model and effort | The main process reads a selected Codex gateway file and passes its settings to Codex, a token included, and never stores, logs or shows a key or token; of the file's settings only its model and effort reach the renderer, as the defaults a thread through the gateway runs, so that the Model setting names what the session runs |
| [ADR-0029](adr/ADR-0029-safari-profile-task-tabs.md) | superseded | Open Safari task tabs in an explicitly connected profile | Connect a named Safari profile in the app and use one Safari App Extension for owned task tabs and exact-tab previews |
| [ADR-0030](adr/ADR-0030-chrome-profile-task-tabs.md) | accepted | Connect a Chrome profile once from the app and open task tabs in it | Pair a Chrome profile once from the app's Settings or a session's notice and let agents open their own inactive tabs in it with its sign-ins, kept until the user disconnects, instead of lending one tab the user picks in Chrome at each connection |
| [ADR-0031](adr/ADR-0031-chrome-only-external-browser-reuse.md) | accepted | Use Chrome for external browser sign-in reuse | Offer the built-in browser and Chrome, with Chrome as the external browser for reusable sign-ins |
| [ADR-0032](adr/ADR-0032-chrome-connector-follows-the-app.md) | accepted | Let Chrome's extension and host follow the app's build | Renew the installed extension, host and registration as the app starts, and have the extension reload itself when its folder names another build than the worker runs, so that an app update needs no step in Chrome |
| [ADR-0033](adr/ADR-0033-helper-holds-its-own-permissions.md) | accepted | Let the native helper hold its own macOS permissions | Have the native helper start itself again in place, responsible for itself, so that its macOS permissions stand on its own signature, outlast app updates and reach nothing else the app starts |
| [ADR-0034](adr/ADR-0034-foreground-control-above-its-window.md) | accepted | Show the foreground control just above the window it is about | Keep the foreground control just above the window the agent controls and directly above it among the windows on the screen, past a display's edges too, at the top of the display only in full screen, for the whole operation and with a stop shortcut of the helper's own, because the user looks for it at that window and puts other windows in front of both |
| [ADR-0036](adr/ADR-0036-session-inboxes-and-child-sessions.md) | accepted | Coordinate sessions through inboxes whose notices travel like presentation notices, and through child sessions, with five tools of the app's toolset | Each session has an inbox the host keeps in the app's data; a message's summary reaches the receiving agent with its next call to the app's tools, beside the user's next message or, while it is idle, in a turn the app starts for the notice alone, and its body only through a tool; sessions list sessions, start children of any provider that start none of their own, end their children and exchange messages through five tools beside the automation tools; messages as user messages, teams and roles, a message queue with delivery workers, a shared task list and native subagents alone were rejected |
| [ADR-0037](adr/ADR-0037-keep-the-providers-own-titles.md) | accepted | Keep the title each provider gives a session, and write one only for a session its provider leaves untitled | Claude Code and Grok Build title their sessions on their own, so the app keeps any title a provider reports, its own or the user's, and asks the session's provider for a title of its own, as ADR-0035 describes, only for a session that has run for a while without one, as every Codex session does; replacing the providers' own titles with the app's, and telling a provider's own title from the user's, were rejected |
| [ADR-0038](adr/ADR-0038-agent-scripts-through-the-debugger.md) | accepted | Run agents' scripts in a page's own context through each engine's debugger session | browser_evaluate runs a script in the top-level document's own context through the DevTools protocol, the embedded engine's own session and the Chrome extension's session for its task tabs, as a tab action under the tab's existing operation, because the console's semantics are what agents expect and both engines already hold such a session |
| [ADR-0039](adr/ADR-0039-providers-from-the-users-own-clis.md) | accepted | Run each provider from the CLI the user installed, or else from a copy the app downloads at sign-in, and keep ADR-0004's other tooling | The app runs each provider from the first CLI of its name on the PATH it runs providers with, where that CLI is at least the oldest version its adapter drives, and otherwise from its own copy of the provider's official build, downloaded into the app's data at sign-in at the version and checksum the app pins, so that users update their providers themselves and the app no longer carries the providers' binaries; ADR-0004's other choices stand, restated here |
| [ADR-0040](adr/ADR-0040-antigravity-through-acp-modes-and-sandbox.md) | accepted | Drive Antigravity through `agy acp` with a process per session, and map the app's modes and sandbox levels onto its modes and terminal sandbox | Each Antigravity session runs `agy acp --process-per-session`, the only form that takes the app's toolset over HTTP; the process runs the terminal sandbox at read-only and workspace-write and none at full access, auto is Antigravity's auto mode where offered except at read-only, where its default mode runs, and a request beyond the level is asked in auto and denied in yolo, as Codex's escalations are; the headless mode, the SDK, a shared process, plan mode, `--dangerously-skip-permissions` and auto mode at read-only were rejected |

## Lessons

| [L-0012](lessons/L-0012-keep-the-title-bar-buttons-after-its-draggable-parts.md) | active | test | Let no draggable part of the title bar come after a button over it in the document | On macOS, Electron applies the page's draggable and non-draggable parts in the document's order, each over those before it, so a button that lies over a draggable part but comes before it in the document takes no presses, whatever its own no-drag and its z-index; put the button after the draggable part, or leave a non-draggable hole in that part beneath it, and check presses with the rule, since Playwright's clicks go past it |
